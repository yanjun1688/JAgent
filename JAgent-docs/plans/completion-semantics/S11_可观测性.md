## 2. 问题背景

日志证据：
- **问题九（reload 风暴）**：`reload_stderr.log:1` `Will watch for changes in these directories: ['D:\\Project\\JAgent']`；`17:21:01~17:29:31` 几乎每秒 `1 change detected`。Uvicorn 监听整个工作区根，日志/数据库/workspace 等运行时产物被纳入 reload 监听 → 反复 reload、端口残留、黑盒测试污染。
- **问题十（日志不可靠）**：
  - 中文显示为 `????`（`harness.log` 大量用户意图乱码，无法还原原始请求）。
  - `status=failed failures=0`（`harness.log:591`）——终态与失败计数不一致。
  - 失败原因只出现在部分日志，无法从事件流重放。

## 3. 为什么这么做

- 可观测性是"弱模型、并发、超时、取消、异常"场景下证明系统正确的唯一手段（INDEX 验收项 10/13）。
- UTF-8 统一写入/读取保证中文意图可还原（问题十 1）。
- 失败计数必须来自事件折叠，与终态一致（问题十 4）。
- reload 目录限制到源码，排除运行时产物，消除风暴（问题九）。

## 4. 做之前先检查影响范围

- 日志写入点：`core/logger.py`、`api/serve.py`、全部 `agent_logger/guard_logger` 调用。
- 中文乱码根因：文件 handler 已是 utf-8；乱码来自**旧日志文件的历史字节** + **Windows 控制台/读取端编码**。修复需：统一读取端 UTF-8 + 必要时清洗旧日志 + 记录 run 级别意图的 JSON 字段（绕开终端编码）。
- 失败计数消费方：`api/routes.py` dashboard（`harness.log:48` `failures=1`）、前端统计、`RunMonitor`。
- reload 配置：`serve.py` 无 `reload_dirs`；由启动命令/`README.md`/`run` 脚本控制。修复点：
  - 添加 `uvicorn --reload-dir harness --reload-dir frontend/src` 或
  - 在 `serve.py` 提供 `main()`（`uvicorn.run(app, reload=..., reload_dirs=[...])`）并更新 README/启动脚本。
- 测试：`tests/test_log_fmtkv_arity.py`、`tests/test_monitoring.py`、`tests/test_api.py`、`tests/test_bug_summary.py`（952 全量基线）。

## 5. 期望达到的目标

1. **统一 UTF-8**：文件写入 + 读取端均为 UTF-8；新增"事件流可重放用户意图"（S05 已落 `intent_raw`，本步保证日志里也能还原——日志 JSON 字段或 UTF-8 修复）。
2. **LLM 调用结构化日志**：每次调用记录 `run_id`、`phase`（classify/plan/revise/answer）、开始时间、结束时间、耗时、异常类型（问题八 观测侧）。
3. **工具调用结构化日志**：记录 `tool`、`operation`、`idempotency_key`、输入摘要、输出摘要、状态（问题十 2）。
4. **失败计数来自事件折叠**：dashboard/统计的 `failures` 从 fold（RunFailed 事件 + tool failures）计算，与终态一致；消除 `status=failed failures=0` 矛盾。
5. **reload 目录限制**：`--reload-dir` 限定源码目录（`harness`、`frontend/src`），排除 `data/`、`*.db`、日志、workspace、缓存。
6. **结构化错误事件**：所有受信组件异常转结构化事件（S09/S10 已做部分，本步补全日志关联）。

## 6. 实现要点

- `serve.py`：
  - 文件 handler 保持 `encoding="utf-8"`；console handler 在 Windows 上确保 `sys.stdout.reconfigure(encoding="utf-8")`（或文档说明用 UTF-8 终端/PowerShell `chcp 65001`）。
  - 提供 `main()` 入口：

```python
def main():
    uvicorn.run(
        "harness.api.serve:app",
        reload=True,
        reload_dirs=["harness", "frontend/src"],
        host="0.0.0.0",
        port=8000,
    )
```

  - 更新 README / 启动脚本，删除"整个工作区根 reload"的用法。
- `core/logger.py`：`fmtkv` 已有；LLM 调用侧新增结构化记录辅助（或在 planner 各阶段调用处打 `run_id/phase/start/end/duration_ms/error`，配合 S10 阶段预算复用计时）。
- 失败计数：在 `routes.py` dashboard 聚合处改为基于 `fold_events`（RunFailed 存在 → failures≥1；tool_results 中 failed/timeout 计数）计算。
- 新增工具调用日志：`ToolExecutor.execute` 内已有的日志补 `operation`（从 input 取 operation/method/action）+ `idempotency_key`（已计算，base.py 有）。
- **禁止事项**：
  - 禁止依赖终端编码显示中文（日志文件与事件存储是权威，终端是显示层）。
  - 禁止把失败计数继续挂在 `consecutive_failures` 计数器（与终态解耦的根因）。
  - 禁止 reload 监听 `data/`、数据库、workspace、缓存（问题九）。
