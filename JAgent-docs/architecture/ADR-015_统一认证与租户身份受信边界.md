## 1. 摘要

当前系统把「我是哪个租户」交给客户端自报的 `X-Tenant-Id` 请求头，并且对 `/api/v1/*`
不做任何认证。渗透测试把这条受信边界打穿后，得到的是**整套控制面的匿名读写 + 工具执行能力**：
匿名读全量数据、匿名创建/删除 workspace、匿名暂停/恢复/确认他人 run、匿名伪造
`operator_id` 写入 append-only 事件流。

本 ADR 的结论：

> **租户身份只能来自服务端验签通过的 JWT Principal；客户端请求头与请求体中的任何身份字段一律不构成授权依据；认证失败必须 fail-closed，不得回退 `default`。**

设计目标是**生产级、但不建用户体系**：

- JWT 资源服务器（Resource Server）：JAgent 只验签，不自建登录、用户库、refresh token；
- 唯一签发方式是**离线 CLI**（现在没有用户，先由运维签发短期 JWT）；未来接 OIDC 时
  只切换 verifier 的 key 来源，不改中间件与业务授权；
- 认证强制执行点是纯 ASGI 中间件，不是逐路由 `Depends`；默认拒绝；
- 复用现有 `ScopedEventStore` 作为租户隔离核心，不重做多租户；
- 不引入 `JAGENT_ENV` / `disabled` / Demo / test 部署模式；测试通过应用装配注入
  `TestAuthProvider`，生产产物里不存在可选免认证路径。

## 3. 设计判断（为什么这样设计）

### 3.1 不建用户体系，用「离线签发 JWT」过渡

现在没有用户，做注册/登录/密码找回/邮箱验证/refresh token 是纯粹的过度设计。
但「没有用户」不等于「可以不认证」——控制面必须默认拒绝。

最务实的做法：

- JAgent 只做 **JWT 资源服务器**；
- 运维用 CLI 离线签发短期 JWT（`sub` / `tenant_id` / `roles` / `exp`）；
- 未来有真实用户/企业 SSO 时，接 OIDC IdP，JAgent 只换成 JWKS 验签，业务代码零改动。

这比「先做一套临时账号密码、以后再推翻」更专业，也比「先不认证、以后再补」安全。

### 3.2 不自建 OIDC / 登录服务

OIDC Provider 涉及授权码、PKCE、会话、同意页、密钥轮换、用户目录，属于独立产品。
本项目不需要。外部 IdP（Keycloak/Entra/Auth0）或离线 CLI 已经覆盖当前阶段。

### 3.3 用中间件，不用「逐路由记得加依赖」

逐路由 `Depends(require_principal)` 的问题是漏加一个端点就裸奔，且新端点默认不安全。
纯 ASGI 中间件在路由前统一验签，**默认拒绝**；新增端点若未登记角色策略直接 403。
这与 Harness「系统强制不依赖执行者配合」的原则一致。

### 3.4 复用 `ScopedEventStore`，只替换身份来源

现有租户过滤是对的。认证层只负责把可信 `tenant_id` 写入 `Principal`，下游
`HarnessAPI.store` 继续用 `ScopedEventStore`。不在业务层重复写 `WHERE tenant_id`。

### 3.5 Bearer-only，不做 Cookie/CSRF

- 浏览器不会自动附带 `Authorization`，Bearer 模式天然免 CSRF；
- 不需要 session store / Redis / CSRF token；
- 前端 token 只存内存 + `sessionStorage`，不落 `localStorage`；
- 代价是 XSS 可窃取 token，用 CSP、React 默认转义、禁止 `dangerouslySetInnerHTML` 缓解。
- 若未来要做同源 Cookie 会话，再单独引入 CSRF 防护，不在本轮混做。

### 3.6 WebSocket 复用同一个 JWT，不做第二套 ticket

浏览器不能给 WS 设置 `Authorization` 头，但可以设置 `Sec-WebSocket-Protocol`。
前端发送 `["jagent.jwt", "jagent.token.<jwt>"]`，后端从第二个子协议取 JWT，
以 `jagent.jwt` 接受连接。这样：

- 不新增 `/auth/ws-ticket` 端点；
- 不新增第二套 HMAC 密钥/nonce 缓存；
- 仍然在握手时验签、校验 run 归属，并在 `exp` 到期时关闭连接。

若某些代理会剥离子协议，再考虑 ticket 作为可选回退，不作为默认实现。

### 3.7 单活签名密钥 + `kid` + 公钥目录

- CLI 生成 RSA/EC 密钥对，私钥只在签发端；
- API 只挂公钥目录 `JAGENT_JWT_PUBLIC_KEYS_DIR`，文件名 `<kid>.pem`；
- 验签按 JWT header 的 `kid` 选 key；
- 轮换：新 key 入目录 → 部署/重启 → 签发新 token → 旧 token 到期后移除旧 key；
- 不做 JWKS 服务、不做多区域密钥服务；未来接 OIDC 时用 `JAGENT_JWT_JWKS_URL`。

### 3.8 不做 refresh token / `jti` denylist（本轮）

- JWT 默认 12 小时（上限 12 小时）到期重新签发即可；
- key 轮换可立即让全部旧 token 失效；
- `jti` 仍写入 token 与审计日志，为未来撤销/追踪留字段；
- 真正需要「立即撤销单个用户」时再加 denylist，不在 P1 增加复杂度。

### 3.9 明确不做什么

- 不做用户名/密码登录、注册、找回密码；
- 不做内置 OIDC Provider；
- 不做 refresh token / session 表；
- 不做细粒度 scope（先用 `viewer/operator/admin` 三角色）；
- 不做每租户独立签名密钥（先用 `tenant_id` claim）；
- 不做多租户管理 UI（CLI 足够）；
- 不做「生产/测试双模式」；测试用应用装配注入，不靠环境变量。

## 4. 核心决策

### D1. `Principal` 是唯一身份载体

```python
# harness/models/principal.py
class Principal(BaseModel):
    subject: str                  # JWT sub
    tenant_id: str                # JWT tenant_id
    roles: frozenset[str]         # {"viewer", "operator", "admin"}
    auth_method: Literal["jwt", "gateway", "test"]
    issuer: str | None = None
    jwt_id: str | None = None
    expires_at: int | None = None
```

- `current_principal: ContextVar[Principal | None]` 替代 `current_tenant`；
- `HarnessAPI.store` 只从 `Principal.tenant_id` 组装 `ScopedEventStore`；
- principal 缺失 → `RuntimeError`（fail-closed），不再回退 `default`；
- `asyncio.create_task` 自动继承 principal，Scheduler 后台任务天然带租户边界；
- `Principal` 只由 AuthMiddleware 构造，业务层不得补字段。

### D2. JWT 认证协议

| 项 | 决策 |
|---|---|
| 传输 | `Authorization: Bearer <jwt>` |
| 算法 | 默认 `RS256`；允许 `ES256`；禁止 `none`；不接受 token 自选算法 |
| 签发方 | 离线 CLI（本轮）；未来外部 OIDC |
| 验签 key | 公钥目录 `<kid>.pem`；未来 `JAGENT_JWT_JWKS_URL` |
| Claims | `iss`、`aud`、`sub`、`tenant_id`、`roles`、`iat`、`nbf`、`exp`、`jti` |
| TTL | 默认 12 小时；上限 12 小时（`JAGENT_JWT_MAX_TTL_SECONDS=43200`） |
| 时钟偏差 | 30 秒 |
| 撤销 | 12h TTL + key 轮换；`jti` 只记录，不做 denylist |
| 租户 | 只认 `tenant_id` claim；不读 `X-Tenant-Id` |
| 租户格式 | `tenant_id` 只允许 `[A-Za-z0-9_.-]{1,64}`；拒绝路径分隔符/控制字符/空值 |
| 角色 | 只认 `roles` 数组；未知角色 fail-closed |

JWT 示例：

```json
{
  "iss": "jagent",
  "aud": "jagent-api",
  "sub": "ops:alice",
  "tenant_id": "default",
  "roles": ["admin"],
  "iat": 1790000000,
  "nbf": 1790000000,
  "exp": 1790003600,
  "jti": "01J8Z3K4M5N6P7Q8R9S0T1U2V3"
}
```

**claims 强校验**：

- `iss`/`aud`/`sub`/`tenant_id`/`roles`/`iat`/`exp`/`jti` 必需；`nbf` 可选，若存在必须校验。
- `tenant_id` 只允许 `[A-Za-z0-9_.-]{1,64}`；拒绝路径分隔符/控制字符/空值。
- `sub` 长度 ≤ 256；`roles` 数量 ≤ 8；JWT 原文长度 ≤ 8KB；超限 → `401`。
- `exp - iat ≤ JAGENT_JWT_MAX_TTL_SECONDS`；未知角色 → `401`。
- `token_use` 若存在必须为 `access`；`id` token 不得用于 API。

配置：

```dotenv
JAGENT_AUTH_MODE=jwt
JAGENT_JWT_ISSUER=jagent
JAGENT_JWT_AUDIENCE=jagent-api
JAGENT_JWT_ALGORITHMS=RS256,ES256
JAGENT_JWT_PUBLIC_KEYS_DIR=/run/secrets/jwt_public_keys
JAGENT_JWT_LEEWAY_SECONDS=30
JAGENT_JWT_MAX_TTL_SECONDS=43200
JAGENT_JWT_TENANT_CLAIM=tenant_id
JAGENT_JWT_ROLES_CLAIM=roles
JAGENT_CORS_ORIGINS=https://jagent.example.com
JAGENT_DOCS_ENABLED=false
```

没有 `JAGENT_ENV`，没有 `AUTH_MODE=test/disabled`。

### D3. 离线签发 CLI

模块：`harness/api/auth/cli.py`，入口 `python -m harness.api.auth.cli`。

```bash
# 1) 生成签名密钥对（私钥 0600，公钥 0644）
python -m harness.api.auth.cli init --out ./secrets

# 2) 签发短期 JWT（私钥只在运维机器）
python -m harness.api.auth.cli issue \
  --key ./secrets/jwt_private.pem \
  --kid <kid> \
  --sub ops:alice \
  --tenant default \
  --roles admin \
  --ttl 12h

# 3) 轮换：生成新 key，把新公钥放进 API 的公钥目录
python -m harness.api.auth.cli rotate --out ./secrets
```

- `init` 生成 RSA 3072（默认）或 EC P-256（`--alg ES256`）；
- `kid` = 公钥 DER 的 SHA-256 前 16 位十六进制；
- `issue` 输出 token 到 stdout，不落盘；
- `rotate` 生成新 key，不删除旧公钥；旧 token 到期后人工移除；
- CLI 不联网、不读写数据库。

### D4. `X-Tenant-Id` 退出授权链

- JWT 模式下完全不读取该头；携带也不影响结果；
- 删除 `app.py:193` 与 `ws.py:27` 的头读取；
- `current_principal` 只允许 AuthMiddleware 写入；
- 旧客户端带该头不报错，但身份不变；文档标注 deprecated。

### D5. 中间件默认拒绝 + 声明式角色策略

```python
class AuthMiddleware:
    async def __call__(self, scope, receive, send):
        if scope["type"] not in {"http", "websocket"}:
            return await self.app(scope, receive, send)
        if self.is_public(scope["path"]):
            return await self.app(scope, receive, send)

        principal = await self.provider.authenticate(scope)
        if principal is None:
            return await self.reject(scope, send, 401)
        if not self.policy.allows(scope["method"], scope["path"], principal.roles):
            return await self.reject(scope, send, 403)

        token = set_current_principal(principal)
        scope.setdefault("state", {})["principal"] = principal
        try:
            return await self.app(scope, receive, send)
        finally:
            reset_current_principal(token)
```

- 公开白名单只允许精确匹配：`/health`；
- 未登记策略的 `/api/v1/*` → 403；
- 未认证请求在 body 解析前返回 401（坏 JSON 也先 401）；
- `/docs`、`/redoc`、`/openapi.json` 默认受保护，生产可通过
  `JAGENT_DOCS_ENABLED=false` 不注册；
- 新增 `GET /api/v1/auth/whoami`：返回 `subject / tenant_id / roles / exp`，
  供前端校验 token 与显示身份。

**装配顺序**：代码中先 `add_middleware(AuthMiddleware)`，再 `add_middleware(CORSMiddleware)`
（Starlette 后加的最外层）；启动时断言 CORS 位于 Auth 之外、Auth 位于路由之前。
否则 CORS 预检会被 401。

角色策略：

| 端点组 | 最低角色 |
|---|---|
| 所有 `GET`（workspaces / runs / events / conversations / analysis / replay） | `viewer` |
| `POST /runs`、`POST /conversations/{id}/messages` | `operator` |
| `POST /runs/{id}/{pause,resume,confirm,feedback}`、`DELETE /runs/{id}` | `operator` |
| `POST/PATCH/DELETE /workspaces` | `admin` |
| `POST/PATCH/DELETE /conversations` | `operator` |
| `POST /operations/retry` | `admin` |
| `GET /auth/whoami` | `viewer` |

### D6. 对象级授权

1. 所有按 `run_id` / `workspace_id` / `conversation_id` 寻址的端点，先经
   `api.store`（`ScopedEventStore`）确认归属；跨租户统一 404。
2. `_schedulers` 注册表绑定 `tenant_id`；`api.get_scheduler(run_id, principal)`
   不匹配返回 `None`；`pause`/`resume` 先 scoped 解析再取 scheduler。
3. `confirm` 忽略请求体 `operator_id`，事件写入 `principal.subject`。
4. workspace `filesystem_root` 必须严格位于 `<base>/<tenant_id>/...`（至少深一层），
   禁止基目录本身作为根（与 finding #7 同源，认证落地后立即修）。
5. `DELETE /runs`、`feedback`、`conversations` 同样先 scoped 解析。

### D7. WebSocket

- AuthMiddleware 处理 `scope["type"] == "websocket"`；
- 前端：`new WebSocket(url, ["jagent.jwt", "jagent.token." + jwt])`；
- 后端从 `Sec-WebSocket-Protocol` 解析第二个值，验签后以 `jagent.jwt` 接受；
- 握手时用 `ScopedEventStore` 校验 run 归属；跨租户关闭 `4404`；
- 连接建立时记录 `exp`，到期主动关闭 `4401`；
- 不接受 `X-Tenant-Id`；
- 若代理剥离子协议，再引入短时效 ticket 作为可选回退。

### D8. 前端

- 首次加载无 token → 显示 token 输入弹窗；
- 调 `GET /api/v1/auth/whoami` 校验 token，显示 `subject/tenant/roles`；
- token 存内存 + `sessionStorage`（不落 `localStorage`）；
- 统一 `authFetch` 附加 `Authorization: Bearer`；401 清 token 并回到输入弹窗；
- `confirmAction` 删除 `operatorId` 参数；
- 退出登录清 token；
- 未来接 OIDC PKCE 时，仅替换「获取 token」的入口，其余不变；
- nginx 增加 CSP、HSTS、`X-Content-Type-Options`、`X-Frame-Options`、
  `Referrer-Policy`。

### D9. 部署

| 项 | 目标 |
|---|---|
| backend 端口 | 宿主只发布 `127.0.0.1:8000:8000` |
| nginx | 8080 对可信网络；TLS 终止；安全响应头 |
| 公钥 | `jwt_public_keys/` 只读挂载 |
| 私钥 | 只在签发端；**绝不**进入 API 容器 |
| 文档 | `JAGENT_DOCS_ENABLED=false` |
| CORS | `JAGENT_CORS_ORIGINS` 显式白名单 |
| 默认租户 | 首次启动可创建 `default` workspace；JWT 必须显式带 `tenant_id=default` |
| 审计 | 认证失败/403 结构化日志 + 计数器 |

### D10. 测试接缝（不是部署模式）

- 生产：`serve.py` 在 import 时执行 `configure_auth_provider(JwtAuthProvider.from_env())`；
- 测试：`app.state.auth_provider = TestAuthProvider(...)`，由 `tests/conftest.py` autouse fixture 注入；
- 生产代码不存在 `JAGENT_ENV=test` / `AUTH_MODE=test` / `disabled`；
- `app.dependency_overrides` 继续用于替换 `get_hapi`，不用于认证。

## 6. 机器强制（AGENTS §6.5）

| 约束 | 强制方式 |
|---|---|
| AuthMiddleware 唯一认证入口 | 断言 `app.user_middleware` 中存在且顺序在 CORS 之后、路由之前 |
| 默认拒绝 | 遍历 `app.routes`，逐一无 token 请求断言 401（白名单显式列出） |
| 认证先于参数校验 | 无 token + 坏 JSON `POST /runs` 必须 401，不是 422 |
| 角色策略完整 | 枚举所有路由，断言每条都命中 `POLICY`；未命中即 fail |
| JWT 签名不可绕过 | `alg=none`、算法混淆、错误签名、未知 `kid`、过期/未来 `nbf` |
| JWT claims 强校验 | 错误 `iss`/`aud`、缺 `tenant_id`/`sub`、未知角色、超长 TTL |
| 跨租户不可见 | 双租户矩阵：workspace/run/event/conversation/analysis/replay/控制端点全 404/403 |
| `X-Tenant-Id` 无效 | 同一 JWT 带不同头，结果与无头一致 |
| `operator_id` 不可伪造 | confirm 后事件 `operator_id == principal.subject` |
| WS 不可越权 | 伪造/过期 JWT 关闭 4401；跨租户 4404；子协议解析正确 |
| 身份唯一写入口 | AST 检查：除 `harness/api/auth/**` 外禁止 `set_current_principal` / 读 `X-Tenant-Id` |
| fail-closed | principal 缺失时 `HarnessAPI.store` 抛错，不回退 `default` |
| 无免认证模式 | 生产配置不存在 `disabled`/`test` 分支；测试 provider 仅由测试装配注入 |
| 私钥不落 API | 镜像/容器检查：无私钥文件；公钥目录只读 |
| 密钥配置 fail-closed | 未配置公钥目录/JWKS 时启动失败 |
| 审计 | 401/403 日志包含 `request_id/subject/tenant/path`，不含 token |

## 7. 验收标准（AC）

- **AC-1**：所有 `/api/v1/*` 无 JWT 返回 401；伪造/过期/错误签名/`alg=none` 返回 401；
  坏 body 也先 401。
- **AC-2**：跨租户读/写/控制全部 404/403；`pause`/`resume`/`confirm`/`feedback` 不可越权。
- **AC-3**：`X-Tenant-Id` 对结果零影响；`operator_id` 由 principal 派生。
- **AC-4**：JWT `iss/aud/sub/tenant_id/roles/exp/nbf/iat/jti` 强校验；未知角色/缺失租户/
  超长 TTL 一律 401。
- **AC-5**：未知 `kid`、密钥轮换、过期 token 行为符合设计；私钥不在 API 容器。
- **AC-6**：WS 由同一中间件认证；跨租户 4404；过期关闭 4401。
- **AC-7**：前端 token 输入、`whoami`、`authFetch`、401 回退、退出登录可用。
- **AC-8**：Docker 默认不公开 8000；公钥只读挂载；nginx 安全头生效。
- **AC-9**：`pytest`、`ruff`、`mypy`、OpenAPI 同步检查全绿；安全负向用例纳入 CI。

## 8. 风险与未决问题

### 8.1 风险

| 风险 | 缓解 |
|---|---|
| 前端 XSS 窃取 token | CSP、React 转义、禁止 `dangerouslySetInnerHTML`、12h TTL、`sessionStorage` |
| 私钥泄漏 | 私钥只在签发端；文件 0600；不入镜像/Git；轮换 runbook |
| 公钥轮换遗漏 | 公钥目录多 key 并存；旧 key 等 TTL 过期后移除；监控 401 |
| 时钟偏差 | 30 秒 leeway；部署 NTP；监控 401 率 |
| 角色映射错误 | IdP/CLI 只允许三个角色；未知角色 fail-closed |
| 现有测试全红 | 统一 conftest 注入 `TestAuthProvider`；不改生产代码路径 |
| 运维签发麻烦 | CLI 一条命令；文档给示例；未来 OIDC 替换 |

### 8.2 默认决策（按此实施）

| 项 | 决策 | 理由 |
|---|---|---|
| 签发方式 | 离线 CLI | 当前无用户，最快达到生产级；未来可无痛切 OIDC |
| 算法 | RS256（允许 ES256） | 兼容性最好，未来 IdP/JWKS 直接可用 |
| Token TTL | 默认 12h，上限 12h | 当前无 refresh token，兼顾安全与运维成本 |
| 前端 | token 输入弹窗 | 不引入 OIDC 依赖；后续可替换为 PKCE |
| 租户 claim | 统一 `tenant_id` | 与现有 `ScopedEventStore` 对齐，最简单 |
| 角色 | viewer / operator / admin | 覆盖读、执行控制、配置管理三档 |
| 撤销 | 12h TTL + key 轮换 | 无用户体系时期足够；`jti` 已留字段 |

如果上述默认项没有异议，P1 直接按此实现，不再等待逐项确认。
