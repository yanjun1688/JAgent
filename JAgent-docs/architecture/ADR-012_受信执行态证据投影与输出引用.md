# ADR-012 — 受信执行态证据投影与输出引用

> **状态**：待评审（关联 DESIGN v3.4）
> **日期**：2026-09-05
> **决策者**：架构导师 + 产品
> **关联**：`JAgent-docs/Dev/DESIGN_v3.4_执行循环韧性与上下文证据治理.md`；ADR-007（执行态与便签解耦）、ADR-008（契约与便签分离）、ADR-009（交付门）

## 背景

v3.4 复核（run `e05087b6`）发现：

1. **受信证据与 LLM 工作上下文耦合在同一份折叠态**。`fold_events` 中 `state.tool_results`/`thought_history` 既被完成门/answer/replay 使用，又被上下文压缩（EpisodeArchived/ContextPruned，`fold.py:418-440`）裁剪。压缩为救 LLM 上下文会误伤证据投影（Replay 时间旅行视图证据消失、answer 细节丢失）。
2. **执行态易失**。`_execute_plan` 的 `results: dict[str, StepResult]`（`scheduler/plan.py:656`）为纯内存；checkpoint 仅记 seq（`ContextCheckpointedPayload.checkpoint_seq`），resume 不从事件重建进度（`base.py:901-904` 只打日志）。崩溃即丢进度。
3. **大输出全量落库/折叠/token 计数**，MCP 无上限；token 估算基于全量 output 误触发紧急压缩。

完成门本身读的是内存 `results`（`plan.py:76-150`），不读被压缩的折叠态——故"压缩→门控误判"并非本次真凶，但证据/上下文耦合是必须根治的架构债。

## 决策

**在事件溯源内新增一层"受信执行态证据投影"，并把大输出收口为 blob 引用；不引入外部 durable 框架。**

1. **证据投影（受信、纯函数、不可被压缩裁剪）**：`fold_events` 新增 `step_evidence`，由 `PLAN_CREATED/REVISED` + `DAG_STEP_STARTED/COMPLETED/FAILED/SKIPPED` + `TOOL_COMPLETED/FAILED/TIMEOUT` 确定性折叠，记录每步骤 `exec_state`、产出引用、失败原因、所属 plan。压缩事件**只裁剪** `thought_history/tool_results`（LLM 工作视图），**永不裁剪** `step_evidence`。
2. **完成门 / resume / Replay 统一读证据投影**：门控不再依赖易失内存 `results` 作为唯一事实；resume 由证据投影确定性重建执行进度；Replay 切片即得完整证据。
3. **大输出 blob 引用**：Tool Layer 对超阈值 output 落 content-addressed blob（workspace 作用域），事件只存 `{summary, ref, sha256, bytes, truncated}` 并写 `OutputBlobStored`；取回经受信只读工具 `fetch_output(ref)`（过 guardrails/幂等/workspace 作用域）。fold 内不做 I/O，投影只持 ref。
4. **不引入 Temporal/LangGraph**：持久化与重建完全由本仓库 append-only 事件 + `fold_events` 承载。

## 受信边界

- 证据投影、exec_state、完成门、resume 重建、blob 引用完整性、压缩裁剪范围 = **受信机械逻辑**，无 LLM。
- episode 摘要文本、局部修复建议、反思、是否 `fetch_output` = **非受信 LLM 决策**，不得参与门控/skip/恢复边界判定（延续 ADR-007/008/009：`TaskState`/`step_tasks` 等便签严禁入受信判定）。

## 后果

**正面**：证据与工作上下文解耦，压缩不再伤证据/Replay；执行态可从事件重建（断点续传）；大输出不污染存储/折叠/token 估算；完全兼容 append-only 与时间旅行。

**负面/成本**：fold 新增投影逻辑（需纯函数 + 全分支测试）；blob 存储抽象需适配本地/远端/沙盒载体；新增事件类型需前后端同步。

**兼容性**：新字段均有默认值，旧事件流折叠行为不变；Replay 投影新增只读字段。
