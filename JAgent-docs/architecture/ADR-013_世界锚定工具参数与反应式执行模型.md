## 1. 摘要

playwright-mcp 的动作参数（`target`/ref/选择器）是**世界锚定值**：它们只在“刚观测到的页面快照”这一上下文里才有意义。Harness 当前的执行模型（Planner 一次性产出**静态参数 DAG**，DagExecutor 按层执行，失败才 revise）假设所有工具参数都是**自包含值**（一眼可定型：url、path、query）。两者不匹配，导致真实浏览器任务反复失败，且任何单一修复（提示规则 / 换模型 / 上视觉 / 反应式循环）都只命中某一层、越修越大。

本 ADR 提出架构级不变量：

> **世界锚定参数只能作用于「系统校验过且仍有效」的观测；使用这类参数的工具必须运行在反应式执行模型下（先观测 → 后取参 → 再动作）。有效性校验归受信系统，元素选择归 Agent。**

并给出三层落地路线（L1 执行模型选择、L2 观测代际校验、L3 能力塑形/Skill），明确与 ADR-011 已交付的池/租约/策略**不冲突、不返工**，且**不引入流程引擎**。

---

## 2. 背景与问题

### 2.1 观测：真实 run 事件复盘（run `14f4683c`，意图「用浏览器搜 bing 查『成都 15 日』」）

事件链摘要（seq 取自 Event Store）：

| seq | 事件 | 内容 |
|---|---|---|
| 7 | ToolCompleted | `browser_navigate` → https://cn.bing.com/ ✅ |
| 11 | ToolCompleted | `browser_snapshot` → 快照 YAML **含** `searchbox "输入搜索词" [ref=e46]` |
| 14-15 | ToolCompleted(unsuccessful) | `browser_type target="search input field on Bing"` → `"..." does not match any elements` |
| 23 | ToolCompleted(idempotent) | 复拍的 snapshot 命中幂等缓存（同一页面状态） |
| 25 | GuardrailTriggered | `browser_fill_form` 缺 `target` → schema 拦截 |
| 30-31 | ToolCompleted(unsuccessful) | `browser_type target="搜索输入框"` → 仍 `does not match any elements` |
| 44-45 | PlanFailed/RunFailed | 3 轮 revise 后 `Steps not achieved`，run 终止 |

**一阶根因**：目标元素在无障碍树中一直存在（`e46` / `searchbox "输入搜索词"`），但模型把自造的“人类描述”填进 `target`。playwright-mcp 0.0.80 的 `target` 契约（已核对该版本真实 inputSchema）只接受两种东西：

1. **快照里的精确 ref**（如 `e46`）；
2. **唯一的 Playwright 选择器**（CSS / `role=` 等）。

schema 里的 `element`（"Human-readable element description used to obtain permission…"）只是给人看的**许可文案，不参与定位**。→ 没有任何“自然语言描述元素”的通道。

**二阶根因（本 ADR 要治的）**：模型在**从未见过快照的 plan 阶段**就被要求把 `target` 定型。静态 DAG 的参数由一次 LLM 调用一次性生成，而浏览器动作的参数必须引用“运行时才产生的观测”——这是**参数分类缺失**，不是模型不够聪明。

### 2.2 为什么“零散修法”会越修越大

| 修法 | 命中层 | 为何不能根治 |
|---|---|---|
| 提示规则“target 用快照 ref” | L4 prompt | 仍是依赖模型遵守的软约束；免费小模型可抄错/漏抄/不看快照 |
| 换更守格式的模型 | L4 模型 | 正确方向之一，但让**核心正确性依赖模型质量**，违背受信边界 |
| 换视觉模型 | L4 + 消息管线 | 目标缺失不是“看不见”；且截图当前以文本/文件路径回传，未作为图像消息进 kernel |
| playwright 自带 vision grounding | L2 后端 | 非 0.0.80 能力，依赖外置视觉模型；仍受 `target` 语义约束 |
| 静态 DAG 内做“执行期选参” | L3 | 结构性不兼容：静态参数在运行时观测出现前已定型；硬做=微流程引擎，违背 ADR |

**共同盲点**：没有把“参数引用了运行时观测”这件事建模出来，于是每类症状都被当成独立问题去各自打补丁。

## 3. 核心决策

### 3.1 工具参数分类（受信元数据，非 LLM 判断）

在工具契约（`ToolDefinition`/`BaseTool`，ADR-010）上增加**受信声明字段**：

```text
grounding: "self-contained" | "observed"
```

| grounding | 判定 | 参数示例 | 执行模型 |
|---|---|---|---|
| `self-contained` | 参数可由意图独立定型 | `http_request.url`、`file_op.path`、`query` | 批量 / DAG 预生成（现状不变） |
| `observed` | 参数引用某次运行时观测内的标识（ref/句柄/选择器） | `browser_type.target`、`browser_click.target`、未来 GUI 工具的句柄 | **反应式**：观测 → 基于观测生成参数 → 动作 → 观测… |

浏览器工具（ADR-011 注册的 22 个一等工具）整体归 `observed`。该字段由工具作者/受信策略表声明，Agent 不可改写。

### 3.2 不变量（受信强制）

> 1. `observed` 工具的动作参数必须是**系统校验过且代际仍有效**的观测内标识；无效 → 结构化拒绝（不可静默猜、不可透传）。
> 2. 使用 `observed` 工具的 Run 由**反应式执行模型**驱动：动作在「看到观测结果之后」的那一轮才被生成。
> 3. 上述两条由受信侧（Tool Layer / Scheduler 选择 / BrowserLease）强制，**不依赖 Agent 配合、不依赖模型质量**。

这延续 v3.3 的「Agent 决策 / 系统强制」分界：**选哪个元素 = Agent 决策；该 ref 是否真实存在且当前有效 = 系统强制。**

### 3.3 与既有架构的关系（不新增引擎、不返工）

- **不引入流程/DAG/编排引擎**：反应式循环复用已存在的 `AgentLoopScheduler`（`harness/core/scheduler/loop.py`，planner 失败时已作为降级路径运行，见 `harness/core/scheduler/plan.py` `_get_or_fallback`）。L1 只是**执行模型选择策略**。
- **不改变 DagExecutor 对自包含任务的批量执行**；`grounding=observed` 才走反应式。
- **ADR-011 交付物零返工**：BrowserPool 租约/隔离/profile 锁/策略过滤/确认/串行全部保留；本 ADR 在其上加“观测代际”与“执行模型选择”，不改变池化语义。
- **状态驱动而非流程驱动**：每次快照/动作是事件溯源中的事件；代际校验产生的 `STALE_STATE` 是结构化错误事件；不落可变“页面状态表”。

## 4. 落地路线

### L1 — 执行模型选择（中小改动，先做）
- 目标：`observed` 工具的任务不再被“静态参数 DAG”误伤。
- 动作：装配时（`deps.start_run` / scheduler 选择点）按 intent 选中工具的 `grounding` 聚合值决定：含 `observed` → `AgentLoopScheduler`（已存在，需补齐事件/清理/确认/终结面接线）；纯 `self-contained` → 现 `PlanningExecutorScheduler`。
- 验收：`14f4683c` 类意图在真跑中，`target` 由“看到 snapshot 后的下一轮”生成。
- 不做：不创建新引擎；不推翻 DAG。

### L2 — 观测代际校验（核心根治，较大，单独立项）
- 目标：即使模型编造/沿用过期 ref，系统也能**拒绝并自我纠正**，正确性不再悬于模型。
- 动作：`BrowserLease` 持有当前页面观测的 `state_generation`；快照类工具刷新它并返回其绑定 ref；动作类工具要求 `state_generation + ref` 成对校验，代际不符/未知 ref → `STALE_STATE` 结构化错误事件 → executor 自动重拍观测并喂回。参考既有 `RetryRunner` 自愈路径。
- 验收：用“恶意/随机 ref”注入也能收敛（系统兜底），不依赖 LLM 输出正确。
- 不做：不把 ref 解析变成新“状态机引擎”。

### L3 — 能力塑形 / Skill（中改动，快速赢面）
- 目标：让免费模型**无需碰 a11y**。
- 动作：复用 `Skill` 概念（`harness/tools/skill.py`），把确定性 80% 包成自包含参数的高层能力：`web_search(query, engine)`、`web_read(url, selector_hint)`、`screenshot(url)`。Skill 内部经受信层完成 snapshot→ref→act（可先走 URL 直达等确定性路径，如搜索 `https://<engine>/search?q=`）。
- 验收：搜索/读页类意图在免费小模型下稳定通过；裸 `browser_*` 保留给强模型/开放浏览。
- 关系：L3 与 L1 互补；L3 减少了必须走 L1 反应式的面，L1/L2 保证剩余开放浏览的健壮性。

## 5. 备选与否决

| 备选 | 结论 | 理由 |
|---|---|---|
| 以视觉模型为主修 | 否决（作主修） | 案例非“看不见”，而是无自然语言定位通道；且截图未以图像消息入 kernel；成本高、收益错位 |
| playwright 官方 vision grounding | 缓办 | 依赖外置视觉模型与更高版本；仍受 `target` 语义约束；不解决免费模型策略 |
| 全部任务改反应式 | 否决 | 自包含任务批量/证据结构化优势丢失；无谓增加 token 与延迟 |
| 放开 `evaluate` / `run_code_unsafe` 做 JS 定位 | 否决（默认） | 违反 ADR-011 安全策略；`evaluate` 仍可由受信配置 + 人工确认放开，但**不作为常规定位手段** |
| “加提示让模型填对”作为唯一修复 | 否决（可作 L1 前廉价加固） | 软约束，依赖模型质量，不满足受信边界 |

## 6. 已知限制 / 非目标（本 ADR 不承诺）

1. ref 生命周期 = 页面状态：导航/刷新/iframe/多标签会令旧 ref 失效——由 L2 代际校验承接，本 ADR 不定义具体失效粒度。
2. 不做反爬/验证码/登录墙绕过；登录态属 ADR-011 persistent 模式职责。
3. 模型分层路由（“便宜模型规划、强模型执行”）是**正交议题**，本 ADR 不展开，仅说明：其不应被当作本问题的主修（见 §2.2）。
4. 不引入 Temporal/LangGraph/任何外部 durable 编排。

## 7. 风险与待确认（评审时逐条回答）

1. `grounding` 字段的归属：工具作者声明 vs 受信策略表按工具名前缀推导（`browser_*` → `observed`）？建议后者起步、前者可演进。
2. L1 的调度选择依据：按 intent 选中工具聚合即可，还是要支持“同 Run 内 DAG 步骤 + 反应式子段”混合？（建议本期只做整 Run 选择，避免 DAG/反应式混跑复杂度。）
3. L2 `state_generation` 的最小语义：整页代际即可，还是细化到“某 snapshot 的某 ref 集合”（后者与 playwright ref 绑定更精确，实现更重）。建议先整页代际 + ref 存在性校验。
4. L3 Skill 首批范围与命名（`web_search`/`web_read`…），及与现有裸工具并存时的可见性策略（白名单/仅默认放开 Skill）。

## 8. 建议推进顺序

1. 本 ADR 评审确认（先解决 §7 开放问题）→ 定稿 v1.0。
2. L1 落地 + `14f4683c` 类回归（含新增 browser_live 场景的断言改为“动作参数必出自本轮观测”）。
3. L3 首批 Skill（搜索/读页）作为快速赢面，降低对免费模型的依赖。
4. L2 单独立项，纳入执行态/受信底座（可与 v3.4 证据投影衔接——观测本身是可折叠的证据）。

## 9. 验收建议（提案性）

- 契约：`grounding` 出现在 ToolDefinition/JSON Schema；`browser_*` 默认 `observed`。
- 单元：纯函数测试分类与代际校验分支（无浏览器）。
- 集成：mock 会话下，过期 ref 触发 `STALE_STATE` 并自动重观测（100% 分支，AGENTS §5.2）。
- 真实（`@pytest.mark.browser_live`，CI 默认 skip）：搜索意图在反应式路径真跑通过；模型“乱填 ref”时由系统兜底收敛。
