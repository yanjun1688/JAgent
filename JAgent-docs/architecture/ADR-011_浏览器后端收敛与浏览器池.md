## 1. 摘要

浏览器能力**只保留一套**：微软官方 [`@playwright/mcp`](https://github.com/microsoft/playwright-mcp)（下称 playwright-mcp）。内置 Playwright Python 浏览器工具（`harness/tools/browser_tool.py` 的 `BrowserTool` / `BROWSER_DEF` / `browser_fn` / `BrowserManager`，5 个 operation）**整体退役删除**。

playwright-mcp 不作为"一个全局共享的 MCP 服务"接入，而是建模为**受信浏览器池（BrowserPool）+ 按 Run 租借（BrowserLease）**，对齐 v3.3 执行载体（ExecutionTarget / ExecutionBackend）模式：

- **每个租约 = 一个独立 playwright-mcp 进程 + 一个独立浏览器实例**，生命周期跟随 Run；
- 工具名全局稳定（`browser_navigate` 等 22 个安全工具注册为一等 `BaseTool`），调用经受信层按 `current_run_id` 路由到该 Run 的租约；
- 两种隔离模式落地：`isolated`（SaaS/CI 默认，临时 profile、即用即毁）与 `persistent`（自托管 A1，真实 Chrome + 按 tenant/workspace 隔离的持久 profile，登录态复用）；
- `cdp`（远端浏览器农场）仅保留枚举与租约提供方接口，本次不实现。

**信任边界不变**：浏览器池是受信组件（Tool Layer），进程生命周期、profile 路径、租约路由、工具过滤、确认挂起、串行强制全部由系统强制，不依赖 Agent 配合；Agent 只看到 22 个过滤后的工具，无法指定 profile 路径、无法访问被禁工具。

## 2. 背景与问题

### 2.1 双后端并存

| 后端 | 形态 | 能力 | 问题 |
|---|---|---|---|
| `browser_tool.py`（内置） | Python playwright，`launch_persistent_context(channel="chrome")`，`BrowserManager` 模块级单例 | 5 ops：navigate/click/type/extract/screenshot | 能力弱（CSS selector、无快照/无障碍树）；单例 = 全局一个浏览器，多租户/多 Run 互串；与 MCP 工具语义重叠 |
| playwright-mcp（MCP） | `npx -y @playwright/mcp` stdio 子进程 | 24 工具：snapshot/find/navigate/click/type/fill_form/hover/select_option/wait_for/tabs/screenshot 等 | 运行时 `npx -y` 首启网络挂死；工具仅作为 `mcp_call` 描述文本而非一等工具；无安全过滤（含 RCE 级 `browser_run_code_unsafe`）；全局单服务多租户共用一个浏览器 |

### 2.2 SaaS 多租户视角的三个硬伤

1. **一个全局 playwright-mcp 服务 = 所有租户共用一个浏览器 profile**。标签页、cookies、登录态互相串扰。playwright-mcp 单实例只持有一个浏览器上下文，这是物理隔离问题，加锁无法解决。
2. **"登录一次长期复用"在 SaaS 中是受控能力而非默认优点**：持久 profile 必须按 tenant/workspace 隔离存储，且同一 profile 任一时刻只能被一个浏览器实例租用（Chrome 约束）。
3. **本机路径假设不成立**：固定 `~/.agent-chrome-profile`、headed、本机 Chrome 是个人工作站模型；云端 worker 需要 headless、临时 profile、Run 结束即毁。

### 2.3 工具接入缺口（ADR-010 后的现状）

- playwright 24 工具未走 `register_tool` 一等注册（`auto_register_tools=False`），只拼接进 `mcp_call.description` 纯文本；Agent 靠 `mcp_call(server_name, tool_name, arguments)` 间接寻址，工具名幻觉/截断问题在历史审计（2026-07-23 runtime audit P0-01/P0-02）中反复出现。
- `McpDynamicTool` 是"来者不拒"的透传壳：无工具过滤、无确认策略、无串行声明、无幂等策略。
- `ToolDefinition.max_parallel` 已声明但 DagExecutor 只有**全局**信号量，per-tool 并发上限无受信强制（planner 仅警告）。

## 3. 决策

### 3.1 拓扑：三种浏览器来源，本次落地前两种

| 拓扑 | playwright-mcp 参数 | 谁拥有 Chrome | 部署形态 | 本次 |
|---|---|---|---|---|
| **① isolated** | `--isolated`（+ `--headless` 云端） | playwright-mcp 子进程内部启动，临时 profile 内存态 | SaaS/CI：即用即毁，零跨租户泄漏 | ✅ 落地（默认） |
| **② persistent** | `--browser chrome --user-data-dir <dir>`（headed 默认） | 同上，但 profile 在磁盘按 tenant/workspace 隔离 | 自托管/A1：登录态复用 | ✅ 落地 |
| **③ cdp** | `--cdp-endpoint <url>` | 外部浏览器农场（Browserbase/Steel/自建 Chrome 集群） | SaaS 上量后浏览器独立集群扩缩容 | ⛔ 仅留枚举 + `LeaseProvider` 接口 + 结构化"未实现"错误 |

**不用长驻 `--port`（Streamable HTTP）模式**：长驻服务适合个人工作站（harness 重启浏览器不死），但与"按 Run 租借、Run 结束即毁"的 SaaS 隔离模型相悖，且引入跨进程租约状态管理。stdio + 每租约独立进程天然随租约销毁。长驻模式在 ADR 中记录为**自托管优化项**，未来可作为 persistent 模式的可选 supervisor 后端，不影响工具层契约。

### 3.2 浏览器池与租约模型

```text
Tenant → Workspace（scope.allowed_tools 白名单决定能否使用 browser_*）
            └─ Run
                 └─ 首次调用 browser_* 工具（懒租借）
                      → BrowserPool.acquire_lease(run_id, tenant_id, workspace_id)
                           ├─ 已有该 run 的租约 → 复用
                           ├─ mode=isolated   → spawn: playwright-mcp --isolated [--headless]
                           ├─ mode=persistent → 校验 profile 租约锁
                           │     ├─ 锁空闲 → spawn: playwright-mcp --browser chrome
                           │     │              --user-data-dir <profile_root>/<tenant>/<workspace>
                           │     └─ 锁被占（同 profile 另一活跃租约）→ 排队（可配置超时）或结构化拒绝
                           └─ mode=cdp        → LeaseProvider 预留，返回 NotImplemented 结构化错误
                      → 返回 BrowserLease（持有 MCP ClientSession + 进程 + 锁）
                 调用期间：BrowserMcpTool.run() 经 current_run_id 取租约 → 租约内 asyncio.Lock 串行 → call_tool
                 Run 终态 / 孤儿回收 / 进程关闭 → BrowserPool.release(run_id)
                      → 关闭 session → 终止 playwright-mcp 进程（Chrome 随之退出）→ 释放 profile 锁
```

关键约束：

- **一个租约一把锁**：同一租约内浏览器工具调用串行（快照/点击不抢页）；不同租约是不同进程，天然并行，无需全局锁。
- **单 profile 单实例**（Chrome 硬约束）：persistent 模式以 `<profile_root>/<tenant>/<workspace>/` 目录为互斥单元，租约锁文件（`*.lock`，含 pid/run_id/时间戳）保证；多进程（多个 serve 实例）场景靠锁文件互斥，同进程靠内存表。
- **懒租借 + 确定性回收**：不起浏览器的 Run 零开销；回收挂在三处——Run 终态事件折叠（scheduler）、服务 shutdown（lifespan）、孤儿 Run 标记（复用 v3.3 `mark_orphans` 机制，启动时清理陈旧锁与泄漏进程）。
- **Agent 不可指定 profile/模式**：模式与 profile 根来自受信配置（env / Workspace 实体），Agent 输入中不接受任何路径参数。

### 3.3 工具注册与安全策略

启动时（lifespan）探测 playwright-mcp 工具清单（spawn 一次性 `list_tools` 或经池预热），经**受信静态策略表**过滤后注册为一等 `BaseTool`（工具名即 MCP 工具名，如 `browser_navigate`）：

| 策略 | 工具 | 处置 |
|---|---|---|
| **硬黑名单（不注册、不可见、不可调）** | `browser_run_code_unsafe`（服务进程内 RCE 级）、`browser_evaluate`（页面内任意 JS 执行） | 注册阶段剔除；Agent 工具清单不存在；直接调用返回结构化错误 |
| **人工确认** | `browser_file_upload`（外发副作用） | `requires_confirmation`，走现有 ConfirmationRequested/Received 挂起流程 |
| **只读（无 side_effects，可 probe）** | `browser_snapshot`/`browser_find`/`browser_take_screenshot`/`browser_console_messages`/`browser_network_requests`/`browser_tabs`(读)/`browser_wait_for` | side_effects=[] |
| **外部副作用（默认放行 + 限流 + 全量事件留痕）** | `browser_navigate`/`browser_click`/`browser_type`/`browser_fill_form`/`browser_hover`/`browser_select_option`/`browser_press_key`/`browser_drag`/`browser_drop`/`browser_file_upload`/`browser_navigate_back`/`browser_handle_dialog`/`browser_close`/`browser_resize`/`browser_network_request` | side_effects=[EXTERNAL] |
| **全部浏览器工具** | — | `max_parallel=1`（受信 per-tool 信号量强制）；**不做幂等缓存**（浏览器动作不可安全重放，`idempotency_key_fields=[]`，失败重试不回放副作用） |

- `browser_evaluate` 提供 env 开关 `HARNESS_BROWSER_ALLOW_EVALUATE=1`（默认关），开启后仍登记为需人工确认；只读页面查询由 `browser_snapshot`/`browser_find`（无障碍树）覆盖，不依赖 evaluate。
- playwright-mcp 官方声明其**不是安全边界**；harness 受信层（过滤 + 确认 + workspace 白名单 + 租约隔离）才是防线。
- Workspace 白名单（`allowed_tools`）支持 `browser_*` 前缀匹配：列 `browser_*` 即放开全部已注册浏览器工具；否则 22 个工具逐个列名。

### 3.4 命令解析：本地固定安装，禁止运行时 npx

- 安装脚本 `scripts/setup_playwright_mcp.py`：将 `@playwright/mcp`（版本固定于项目根 `package.json`）安装到**项目内 `node_modules`**，校验可执行；失败输出明确安装指引。
- 命令解析顺序（受信，纯函数可单测）：`HARNESS_PLAYWRIGHT_MCP_CMD` env 覆盖 → 项目 `node_modules/.bin/playwright-mcp(.cmd)` → 全局安装 → 抛出带安装提示的结构化错误。Windows 经 `cmd /c` 规范化（复用 `_connect_stdio` 现有逻辑，抽取为共享 `_normalize_command`）。
- `mcp_servers.json` 中 **移除 playwright 条目**（改由 BrowserPool 管理）；memory/fetch 保留 stdio MCP 路径不变。

### 3.5 DagExecutor per-tool 并发强制（顺带修复）

`ToolDefinition.max_parallel` 由"仅 planner 警告"升级为受信强制：DagExecutor 在全局信号量之内增加 per-tool `asyncio.Semaphore(tool_def.max_parallel)`（按工具名懒创建），浏览器工具 `max_parallel=1` 即同进程内跨 Run 也排队等候各自租约——注意租约隔离下不同 Run 的浏览器调用本就指向不同进程，per-tool=1 是额外的保守兜底，防止同 Run 并行步骤抢同一租约（租约内锁为第一道，此为第二道）。

## 4. 受信边界对照

| 能力 | 归属 | 说明 |
|---|---|---|
| 决定点哪个元素、填什么内容 | Agent（非受信） | 工具参数由 LLM 生成 |
| 工具是否存在/可见 | 受信（注册过滤） | 黑名单工具不注册 |
| 浏览器进程生死、profile 路径、模式 | 受信（BrowserPool） | Agent 不可触达 |
| 调用路由到哪个浏览器 | 受信（current_run_id → lease） | Agent 无法跨 Run 访问 |
| 危险动作挂起确认 | 受信（ToolExecutor 确认流） | 不依赖 Agent 自觉 |
| 串行/互斥 | 受信（租约锁 + per-tool 信号量 + profile 锁文件） | 系统强制 |
| 副作用事件 | 受信（ToolCalled/Completed/Failed + Confirmation 事件） | 全部经 Event Store |

## 8. 已知限制

1. playwright-mcp 非安全边界：恶意页面可利用浏览器漏洞；隔离靠进程 + profile 分离，不靠 mcp 自身。
2. 单 profile 单实例：persistent 模式同一 tenant/workspace 的并发 Run 排队（默认 30s）或拒绝；需要并行请用 isolated 模式或未来 cdp 农场。
3. 不提供任意代码执行：`browser_run_code_unsafe` 永不注册；`browser_evaluate` 默认禁用。
4. 不做反爬/验证码绕过；不做 docker 内假浏览器。
5. 浏览器动作不幂等缓存：网络重试不会重放点击（由 RetryRunner 对浏览器工具关闭重试或仅对连接类错误重试，策略在实现时按工具分类细化）。
